# Batman Panel — نسخه‌ی توسعه‌یافته‌ی ۱٫۳٫۰

این پروژه روی فایل‌های پیوست‌شده‌ی شما و همان پنل شبکه‌ای ساخته شده است؛ با آن‌که نام/لینک عمومی Antagonix قابل تنظیم است، این برنامه **جایگزین API یا پنل مدیریت کانتینر Antagonix نیست**.

## امکانات مرحله‌ی دوم

- انتخاب سقف تعداد خروجی از ۱ تا ۱۱ (در صورت فعال‌بودن XHTTP) و انتخاب پروتکل‌ها از صفحه‌ی «تنظیمات مدیر». این فیلتر روی لینک‌های تکی و اشتراک اعمال می‌شود؛ خروجی‌های سازگار با هر کلاینت ممکن است زیرمجموعه‌ای از انتخاب باشند. چک‌باکس‌ها فقط خروجی کانفیگ را کنترل می‌کنند و هسته/شنونده‌های شبکه را روشن یا خاموش نمی‌کنند؛ برای پروتکل‌هایی که در خروجی سازگار حذف می‌شوند، از لینک کامل/خام همراه با کلاینت سازگار استفاده کن.
- کاتالوگ فقط از پروتکل‌های پیاده‌سازی‌شده در همین کد ساخته می‌شود. سقف ثابت قبلی برداشته شده؛ `Trojan-TCP` و `ShadowTLS-VLESS` که پشت سقف ۸ مورد پنهان می‌ماندند اکنون قابل انتخاب‌اند. `VLESS-TCP` و `VMess-WS` نیز از مسیرهای واقعیِ موجود در backend ارائه می‌شوند. پروتکل اختیاری `VLESS-XHTTP` هم فقط وقتی `ENABLE_XHTTP=true` باشد، باینری Xray در دسترس باشد و میزبان اجازه دهد، در کاتالوگ ظاهر می‌شود؛ این گزینه منابع بیشتری می‌خواهد و برایش از خروجی کامل/خام و کلاینت سازگار با Xray استفاده کن؛ خروجی سازگار v2ray یا Sing-box لزوماً آن را دربرنمی‌گیرد. برچسب «مسیر ساخته‌شده» به معنی آزمون موفق از اینترنت کاربر نیست؛ دامنه/DNS، TLS، فایروال، پورت و پشتیبانی میزبان همچنان باید درست باشند.
- تنظیم عنوان پروفایل و فاصله‌ی پیشنهادی به‌روزرسانی اشتراک؛ این مقدار یک سربرگ پیشنهادی است و زمان واکشی نهایی را کلاینت تعیین می‌کند.
- کنترل سقف حساب‌ها و پیش‌فرض ساخت کاربر (حجم، روز اعتبار، سقف Mbps و اتصال هم‌زمان). این سقف در خود پنل اعمال می‌شود و منابع میزبان را رزرو یا افزایش نمی‌دهد.
- تنظیم تأخیر اولیه‌ی TCP keepalive برای نشست‌های جدید؛ `TCP_NODELAY` روی رله‌ی TCP فعال است. این بهینه‌سازی تضمین‌کننده‌ی سرعت اینترنت/تونل یا پینگ مقصد نیست. آزمون خانه فقط رفت‌وبرگشت API پنل تا مرورگر را اندازه می‌گیرد، نه سرعت تونل.
- خانه‌ی پربارتر با دسترسی سریع، رویدادهای اخیر، داده‌های میزبان و آزمون پاسخ API.
- هشت پس‌زمینه‌ی داخلی با حال‌وهوای گاتهام/خفاش؛ سه پس‌زمینه‌ی جدید در `assets/bg6.jpg` تا `assets/bg8.jpg` هستند.
- صفحه‌ی عمومی ساب از نو طراحی شده: خلاصه‌ی سهمیه، حجم باقی‌مانده، آپلود/دانلود واقعی، وضعیت و هشدار نزدیک‌شدن به انقضا/اتمام حجم؛ لینک‌های اصلی و فرمت‌های v2ray، Full، Raw، Clash Meta و Sing-box با کپی و QR؛ دریافت یک‌جای کانفیگ‌ها به‌صورت TXT و راهنمای شروع سریع. نمودار ساختگی روزانه/هفتگی حذف شده و مقدارها snapshot زمان بارگذاری‌اند. مسیرهای خروجی کلاینت‌ها تغییر نکرده‌اند؛ مرورگر به‌جای متن خام، همین پورتال گرافیکی را نشان می‌دهد.
- بخش اشتراک مدیر به Link Studio تبدیل شده: جستجوی سریع کاربر، نمایش فرمت‌ها، کپی/QR، کپی گروهی لینک‌ها یا کانفیگ‌ها، محوکردن لینک‌ها برای حریم دیداری و پیش‌نمایش پورتال کاربر.

تنظیمات مدیر در `panel-settings.json` داخل `BK_DATA_DIR` ذخیره می‌شوند و با فایل دسترسی محدود نوشته می‌شوند. در هر استقرار از مسیر داده‌ی پایدار استفاده کن تا کاربران، رمز مدیر و تنظیمات بعد از راه‌اندازی مجدد باقی بمانند.

## اجرا

نیازمندی: Node.js نسخه‌ی ۱۸ یا جدیدتر.

```bash
npm install
npm start
```

در پنل میزبان، متغیرها را در بخش Environment/Variables تنظیم کن. فایل `.env.example` فقط نمونه است؛ برنامه بدون `dotenv` آن را خودکار نمی‌خواند.

- `PORT` را معمولاً میزبان خودش تنظیم می‌کند؛ مقدار پورت برنامه را با همان مقدار هماهنگ نگه دار.
- `BK_DATA_DIR` را روی فضای پایدار میزبان قرار بده.
- برای نخستین راه‌اندازی عمومی، یک `PANEL_SETUP_KEY` قوی تنظیم کن و آن را فقط در فرم راه‌اندازی اولیه وارد کن.
- `HOST_PANEL_URL` را به لینک واقعی پنل میزبان خودت تنظیم کن؛ مقدار پیش‌فرض فقط صفحه‌ی ورود عمومی Antagonix است، نه صفحه‌ی اختصاصی سرورت.
- مقادیر CPU/RAM/دیسک پیش‌فرض (`25%`, `200 MB`, `5 GB`) بر اساس اطلاعاتی است که خودت دادی و قابل تغییر است؛ برنامه سهمیه‌ی میزبان را ایجاد یا افزایش نمی‌دهد.

## محدودیت مهم درباره‌ی Antagonix و پروتکل‌ها

برنامه به‌صورت واقعی لینک‌های پروتکل‌هایی را می‌سازد که در هسته و رله‌ی TCP خودش پیاده‌سازی شده‌اند، اما دسترسی واقعی به شبکه از داخل پنل میزبان تضمین نمی‌شود. پیش از استقرار، قوانین Antagonix را درباره‌ی اجرای پردازه‌های جانبی، دانلود باینری، پورت‌های عمومی و UDP بررسی کن. اگر میزبان فقط یک پورت TCP وب در اختیار بگذارد یا UDP را مسدود کند، همه‌ی روش‌ها قابل‌دسترسی نخواهند بود. نسخه‌ی فعلی به API مدیریتی خصوصی Antagonix وصل نیست و ساخت/حذف/تمدید/توقف کانتینر را ادعا نمی‌کند.

محدودیت ۲۰۰ مگابایتی که اعلام کردی ممکن است برای چند هسته‌ی جانبی هم‌زمان تنگ باشد. در صورت کمبود RAM، پروتکل‌ها/هسته‌هایی را که واقعاً در میزبان مجازند نگه دار و مصرف واقعی را با آمار میزبان مقایسه کن.

## دقت آمار و عملکرد

مصرف CPU/RAM از cgroups خوانده می‌شود اگر کانتینر آن اطلاعات را در اختیار برنامه بگذارد؛ در غیر این صورت برآوردی از خود برنامه نمایش داده می‌شود. «داده‌های برنامه روی دیسک» اندازه‌ی پوشه‌ی داده است، نه اندازه‌گیری قطعی کل دیسک حساب میزبانی. سهمیه‌های نمایش‌داده‌شده جای آمار رسمی میزبان را نمی‌گیرند. سرعت نهایی به سرور، شبکه، مسیریابی، کلاینت و محدودیت‌های میزبان وابسته است؛ انتخاب پروتکل یا keepalive سرعت مشخصی را تضمین نمی‌کند.

## فایل‌ها

- `index.js` — نسخه‌ی اصلیِ تک‌فایلی؛ رابط و منطق پنل در آن embed شده است.
- `assets/bg6.jpg`، `assets/bg7.jpg` و `assets/bg8.jpg` — سه پس‌زمینه‌ی جدید.
- `package.json` — فرمان اجرا و وابستگی‌ها.
- `.env.example` — نمونه‌ی متغیرهای محیطی؛ مقادیر واقعی را در پنل میزبان بگذار و عمومی نکن.
